# Build roadmap

The build is a stack of small pull requests. Each one ends in a check that `agent-device` or a JVM test runs, and no pull request starts until the one below it is green. Milestones run riskiest first: the private protocol, then the core loop, then the surfaces that depend on it.

Module names come from `docs/design/sketch/settings.gradle.kts`. Flow scripts live in `flows/` as agent-device `.ad` files and run with `agent-device test 'flows/*.ad'` (`verification.md`). The TriFold AVD is the one `scripts/create-trifold-avd.sh` creates (`verification.md`, "The TriFold AVD").

## Rules for every pull request

- The pull request adds or updates the flow script that proves it, and the flow runs in CI on the TriFold AVD.
- No pull request calls a `web-remote` endpoint. The lint enforces this.
- A protocol change adds a capture to `:fake-amp` and a replay test.
- A new pane or machine tab adds a branch to the exhaustive `when` in `:app`, so a missing branch fails to compile. A new tool card or wire decoder adds one entry to the `ToolCards` or `WireDecoders` map, and the duplicate-key test fails on a clash.
- UI changes run the form-factor sweep and update screenshot baselines on purpose, never by default.

## Answers that shaped M1 to M4

The second protocol spike settled these before any app code exists (`spikes/protocol/RESULTS.md`, rows S15 to S20):

- `/request/rpc` accepts only `client_append_user_msg`. Every other write, including approval answers, cancel, rename, and push subscription, goes over the thread socket.
- The server deduplicates a resent client `messageId`: a resend returns the same `seq` and leaves one copy in the transcript. The outbox can resend sends safely.
- After loading paged history, resume from `thread.data.v`. Resuming from 0 replays every message.
- Plugin dialogs (`plugin.ui.request_added`, `plugin.ui.respond`) work end to end, and the user actor reports `indicator{kind: "action-required"}` while one waits.
- `client_filesystem_*` list, read, and write work. Range reads and `getThreadFileURLs` do not.
- The `network dump` line format is known (`verification.md`).

One question is still open. The tool approval wire format comes from the web bundle and was never observed, because the workspace's custom model routing failed every agent turn during the spike. Built-in ask rules also did not gate the S4 runner turn (`RESULTS.md` row S15), and Amp asks for approval only when a policy plugin requires it (Amp's docs). M4 therefore gates on the S15b plugin dialog flow until `bun spikes/protocol/s15-approvals.ts` reruns on a working model.

## The relay is ahead of M9

The push relay is built and tested. Its 41 tests pass, and `relay/scripts/smoke.sh` checks a deployment end to end. A deployment holds the service account of the Firebase project that the app's `app/google-services.json` (gitignored) belongs to.

Spike S11b now passes end to end (`spikes/protocol/RESULTS.md`, "S11b rerun on the TriFold"). A live turn ended, Amp sent a VAPID-signed Web Push to the relay, the relay forwarded it over FCM, and the TriFold posted the notification on the Finished channel 8 s after the turn ended. Amp sends `TTL: 86400`, `Urgency: normal`, and no `Topic`. Its VAPID public key is recorded there and can become `AMP_VAPID_PUBLIC_KEY`, which makes the relay reject pushes not signed by Amp.

### Android network log line format (S20)

No tag is required and any priority works. The only filter is the app's PID, so the line must come from the app process. Emit one logcat line per finished HTTP exchange: a JSON object with the request and response fields, then `duration=<ms>` as plain text outside the JSON.

```
10-22 14:03:07.123 I/AgentNet( 4321): {"method":"POST","url":"https://api.example.com/v1/items?x=1","status":201,"headers":{"content-type":"application/json"},"requestBody":{"name":"a"},"responseBody":{"id":7}} duration=87
```

The part after `): ` is what the app logs. The prefix comes from `logcat -v time`. Rules, read from `src7.js` and confirmed by running the copied functions:

- The parser takes the JSON from the first `{` to the last `}` on the line, so keep other braces off the line.
- Method comes from `method` or `httpMethod`, URL from `url` or `requestUrl`, and status from `status`, `statusCode` or `responseCode` (an integer or a 3-digit string).
- Duration is read only by `/\b(?:duration|elapsed request\/response time, ms)[:= ]+(\d+)\b/i`. A JSON key such as `"durationMs":87` is ignored, so write `duration=87` as text.
- Headers are read from the first present of `headers`, `requestHeaders`, `responseHeaders`. That is one field per line, so merge request and response headers or pick one.
- The request body is the first present of `requestBody`, `body`, `payload`, `request`. The response body is the first present of `responseBody`, `response`. Objects are stringified.
- An ISO timestamp anywhere on the line beats the logcat prefix time.
- There is no request/response pairing. Two lines make two entries. On Android, a missing status or duration is filled from lines within ±5 (or ±12 with a matching `packet id <n>`), which leaks values between neighbouring requests. One complete line per exchange avoids that.
- Each of `raw`, `headers`, `requestBody` and `responseBody` is truncated to 2048 characters plus `...<truncated>`. Only the last 4000 lines are scanned, and the default is 25 entries (maximum 200).
- `raw`, the whole line, is returned at every `--include` level, so do not log secrets. `AGENT_DEVICE_APP_LOG_REDACT_PATTERNS` is agent-device's redaction hook.
- `--include summary` returns method, url, status, timestamp, packetId, durationMs, raw and line. `headers` adds headers, `body` adds both bodies, and `all` adds everything.
- A message containing `\n` becomes several logcat lines (inferred), so keep each exchange on one physical line.
